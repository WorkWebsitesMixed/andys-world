The regular class's weighted evaluation matrix (score × weight, highest total wins) is genuinely objective — a real improvement over "I just like this one." This session adds the question a single matrix run never answers: how confident should you actually be in that winner? A decision that only wins because of how the weights happened to be set isn't as solid as one that wins no matter how you weight it.

<Callout type="exam" title="Why this matters" id="why">
  <ExamLink to="project">Component 2 Criterion 3</ExamLink> is worth 20 marks — the single largest design criterion — and a distinction-level selection needs to be traceable to spec points, the same "traceable" standard from Term 1's SK6 specification work, now applied to a design decision instead of a spec point.
</Callout>

<KeyTerms terms={[
  { term: "Weighted score", definition: "Score × weight, summed across every specification point, for one idea. The formula behind the regular class's evaluation matrix, made explicit." },
  { term: "Sensitivity check", definition: "Re-running a decision matrix with different (but still reasonable) weights to see whether the winning idea changes. If the winner stays the same across several plausible weightings, the decision is robust. If it flips easily, the original selection was more fragile than the single matrix run suggested." },
  { term: "Pugh matrix", definition: "A concept-selection method (introduced in T1 SK8): pick a datum idea, score every alternative as better (+), the same (0), or worse (−) relative to it on each criterion. Faster to build than a weighted matrix and makes the comparison to a baseline explicit." },
]} />

<Section title="The weighted matrix, formalised" icon="🧮" id="weighted">

<Formula
  name="Weighted score for one idea"
  equation="\text{Total} = \sum_{i} (\text{weight}_i \times \text{score}_i)"
  note="Total = the idea's overall weighted score, summed across every specification point. weight_i = the importance assigned to specification point i (e.g. out of 10 total across all points). score_i = how well this idea meets point i, typically 0–3 (0 = fails, 3 = exceeds). Σ (sigma) means 'sum over every point i' — add up weight × score for every row, not just one."
/>

This is exactly what the regular class's matrix table computes row by row — writing it as one formula makes clear that changing a single weight changes every idea's total, which is exactly why a sensitivity check matters: the "winner" is a function of the weights you chose, not an absolute fact about the ideas.

</Section>

<WorkedExample title="Sensitivity check on the cyclist organiser matrix">

Using T1's evaluation matrix (wall-mounted pegboard A: 27, freestanding tower B: 26, hanging frame C: 17) — A wins, but only by 1 point over B. That's close enough to check.

**Re-weighting:** the original matrix weighted "holds 4 kg" at 3 and "easy to mount/unmount gear" at 3. Suppose the user, on reflection, cares more about ease of mounting/unmounting (daily use) than raw load capacity (rarely tested near the limit) — swap the weights: "holds 4 kg" drops to weight 2, "easy to mount/unmount" rises to weight 4.

Recalculating just those two rows: Idea A — holds 4kg (3×2=6) + easy mount (2×4=8) = 14 (was 9+6=15). Idea B — holds 4kg (3×2=6) + easy mount (3×4=12) = 18 (was 9+9=18). With the other two rows unchanged (6+6=12 for both A and B), new totals: A = 26, B = 30 — **B now wins**.

**What this tells you:** the original selection (A) was not robust — it depended on weighting load capacity above ease of use. A distinction-level justification would report this honestly: "Idea A wins under the original weighting, but the result is sensitive to how heavily ease-of-mounting is weighted against load capacity — I am selecting A because [a stated reason for why load capacity should be weighted higher for this specific user], not because the matrix gave a single unambiguous answer."

</WorkedExample>

<Extension title="Taste beyond: the Pugh matrix and weighted-objectives method in engineering">

Real concept-selection in engineering rarely stops at one weighted matrix run. The **Pugh matrix** (T1 SK8) checks ideas against a baseline rather than in isolation — useful when you want to know "is this actually better than what already exists," not just "which of these three is best." The **weighted-objectives method** (what the regular class's matrix already is, formalised) is preferred when there's no natural baseline and every criterion needs its own explicit importance. Professional teams often run both: a Pugh matrix to narrow a wide field of concepts down to two or three strong candidates, then a weighted-objectives matrix for the final decision between those few — because a Pugh matrix is fast but coarse (+/0/−), while a weighted matrix is slower but more decisive between close alternatives.

</Extension>

<Activity title="Weighted selection, sensitivity check, TA-prep" time="45 min" grouping="Individual, HOD circulating" materials={["Your Term 1 idea sketches", "Your specification", "Calculator"]}>

**0–10 min — Preview.** Recap developing vs generating ideas, and the regular class's evaluation-against-spec model.

**10–25 min — Weighted selection.** Build your evaluation matrix: ideas as columns, 4–6 spec points as rows, weights assigned, scores 0–3, totals calculated.

**25–35 min — Pugh-matrix taste.** Recap T1 SK8's Pugh matrix method. Note one reason you might prefer a Pugh matrix over a weighted matrix at an earlier stage of narrowing ideas down.

**35–45 min — TA cue rehearsal + Challenge.** Read the TA prep box, then complete the challenge: run your weighted matrix, then a sensitivity check — change one or two weights plausibly and see whether the winner changes. Write one sentence reporting the result honestly, whichever way it goes.
</Activity>

<Support title="TA prep: evidence, not preference">

**Common error to watch for:** a peer picks an idea first, then builds a matrix that happens to justify it — scores quietly nudged to fit the preferred outcome rather than assessed honestly.

**Your tutoring cue:** *"Which spec points matter most, and which idea wins on them?"* — asked BEFORE scores are filled in, this forces the weighting decision to happen independently of which idea the peer already likes, which is the actual discipline an objective matrix depends on.

</Support>
